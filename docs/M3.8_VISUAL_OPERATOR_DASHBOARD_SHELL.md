# M3.8 Visual Operator Dashboard Shell

## Status and purpose

**Status: completed local-only visual shell; non-operational.** M3.8 delivers
the first 24Seven.FM Operator Dashboard surface: a responsive, keyboard-
accessible Programming Control Plane workspace that makes the four separately
deployable planes visible without activating or controlling any of them.

It is the implementation and evidence record for [M3.8 in the authoritative
roadmap](ROADMAP.md#m38--visual-operator-dashboard-shell). Completion does not
authorize M3.9, a migration, persistence activation, worker, staging action,
or any other operational change.

## Delivered local-only visual boundary

The dashboard retains an authenticated station context derived from the
existing local session/RBAC contract. It selects only stations authorized for
that context; an unavailable requested context is presented without exposing
another station's data. All entity-facing contracts remain `id + station_id`:
out-of-scope resources return `not_found` and internal cross-station references
remain `station_reference_forbidden`.

It provides these semantic, keyboard-navigable views:

- **System overview:** four-plane architecture and the distinction between
  local contracts and unavailable future planes.
- **Programming Control Plane:** a read-only explanation that M4 publication
  and M5 execution are outside this shell.
- **Media Workspace:** the M3 asset lifecycle plus asset/source, processing,
  normalization, cue/fade, and metadata-candidate/resolution contract status.
  Every item is explicitly labelled fixture/example or disabled; no asset,
  fixture candidate, source reference, file, tag, or live result is loaded.
- **Playout & Automation Runtime, Source Encoder Layer, and Listener-Facing
  Icecast Layer:** clearly unavailable views with non-interactive statements
  of their separate future authorization requirements.
- **Audit / operational evidence:** a content-free evidence-field shape only;
  it contains no live audit event.

The visual shell uses native links, headings, landmarks, a skip link, focused
keyboard styles, responsive layout, live status announcements, and explicit
unavailable state labels. It introduces no dashboard route for M3 record data
or any cross-plane operation. Existing local sign-in/sign-out/session handling
remains bounded to access context and does not expose a capability to start
another plane.

## Hard operational boundary

No dashboard action can ingest or access media; resolve a source; launch a
worker, subprocess, container, parser, or media tool; call a provider; alter
M4 scheduling/publication; alter M5 runtime/DSP; configure an encoder, relay,
or Icecast mount; publish dynamic metadata; run a migration; activate
persistence; deploy; or affect listeners. It performs no external provider,
filesystem, media, processing, runtime, encoder, relay, Icecast, migration,
or deployment adapter call.

The shell has no raw media/title/artist/album/filename/path/URL/tag/payload,
credential/token/CSRF value, provider payload, or raw SQL output. Its evidence
view permits only action type, station ID, opaque entity ID, state/category,
and safe timing/count field labels. PostgreSQL remains the sole future live
persistence target, and Icecast 2.x remains the sole future listener-facing
platform direction. No SQLite, SAM, PAL, SHOUTcast, or legacy runtime
dependency was introduced.

## Validation evidence and next gate

Focused UI/API tests verify the shell, accessible navigation/focus semantics,
station-context guard, fixture and unavailable labels, content-free display,
and absence of dashboard station-data or operational route paths. The full
local check suite covers the earlier M3 station isolation, `not_found`,
`station_reference_forbidden`, idempotency, provenance, failure/retry, and
disabled-boundary contracts.

The next permissible item is separately approved **M3.9 — isolation,
idempotency, failure, and recovery validation**. Any attempt to activate a
worker, persistence, provider, staging target, schedule, runtime, encoder,
Icecast, deployment, or production capability requires its own explicit
approval and content-free evidence.
