# M4.2 Catalog and Asset-Eligibility Acceptance Decision

## Decision and boundary

**Status: accepted 2026-08-05 UTC; local-only and non-operational.** This
decision accepts [M4.2's catalog and asset-eligibility
boundary](M4.2_CATALOG_AND_ASSET_ELIGIBILITY_BOUNDARY.md) under its separate
owner approval. It accepts only a deterministic, in-memory Control Plane
projection from M3 asset eligibility to opaque M4 candidate identity.

It authorizes no M4.3 clock/template work, catalog persistence, migration,
database connection, media or metadata access, schedule generation, approval,
publication, runtime consumption, encoder, Icecast, deployment, or production
activity.

## Accepted evidence

| Required criterion         | Accepted evidence                                                                                                                       |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| M3 eligibility boundary    | Only an M3 asset in `ready_for_schedule_use` with its immutable same-station revision produces a candidate.                             |
| Supersession and rejection | `superseded` and every non-ready lifecycle state return controlled, content-free rejection categories.                                  |
| Station isolation          | Public out-of-scope reads return `not_found`; trusted internal ownership or relation mismatches return `station_reference_forbidden`.   |
| Immutable projection       | Candidate and evidence values are frozen and expose only opaque identity and safe eligibility fields.                                   |
| Content-free evidence      | Tests reject content-bearing output; no source, media, metadata, path, credential, token, SQL, or raw error field is returned.          |
| Four-plane non-dispatch    | Static coverage verifies no filesystem, network, persistence, worker, runtime, encoder, relay, or Icecast adapter import or invocation. |

The focused compiled test and full repository quality suite pass. M4.2 did not
connect to PostgreSQL, execute a migration, access media or a filesystem, call
a provider, start a worker or service, publish a schedule, or contact a
runtime, encoder, relay, Icecast, listener, DNS, deployment, or production
system.

## Next gate

At the time of this decision, **M4.3 — Deterministic 24-hour clock and
template model** was the next sequential milestone and required a new explicit
owner approval before work began. This acceptance decision did not grant or
imply that approval.
