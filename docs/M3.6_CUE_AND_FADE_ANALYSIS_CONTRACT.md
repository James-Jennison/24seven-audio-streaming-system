# M3.6 Cue and Fade Analysis Contract

**Status: local-only, disabled, and non-operational.** M3.6 defines a
station-scoped cue/fade-analysis request/result contract. It does not read or
measure media, detect cues, modify audio, apply playout settings, start a
worker, or activate persistence.

The contract accepts only an M3.4-approved opaque processing job whose same-
station asset revision is approved and whose source validation is valid. A
request contains opaque IDs, the `cue-fade-fixture-v1` profile, a safe analysis-
version ID, and a bounded retry count. It accepts no filename, path, URL, tag,
waveform, payload, metadata, credential, or token.

Fixture-only recommendations contain bounded duration, cue-in, intro-end,
outro-start, cue-out, fade-in, fade-out, confidence, confidence category,
quality, and analysis-version values. Validation requires safe ordering and
fade-window relationships, bounded confidence/category agreement, and a
supported profile. These values are derived future suggestions, not measured
facts or approved runtime settings. A fixture result is explicitly marked
`analysisPerformed: false` and `deterministic_fixture`; it never claims real
cue or fade detection.

Requests, results, and evidence are keyed by `id + station_id`. Out-of-scope
reads return `not_found`; internal cross-station relationships return
`station_reference_forbidden`. Duplicate station-local requests return the
original immutable result, while a conflicting idempotency key is rejected.
Failure, quarantine, and retry categories are bounded. A retry remains a
future explicit authorization and never dispatches work. Results/evidence are
append-only intent and cannot overwrite an asset revision, provenance,
normalization suggestion, or prior cue/fade suggestion.

The read-only API/UI reports disabled, fixture-only cue/fade status. There is
no upload, analyze-now, dispatch, worker, filesystem, network, provider,
schedule, runtime, encoder, relay, Icecast, or listener-facing control.
Evidence contains only action, opaque ID, station ID, profile/version, safe
category/count, UTC time, and bounded technical outcome fields.

M3.6 remains exclusively in the Programming Control Plane. It cannot mutate
M4 publication, M5 playout/DSP, the Source Encoder Layer, or the
Listener-Facing Icecast Layer. PostgreSQL remains the sole future live store;
no SQLite, SAM, PAL, SHOUTcast, migration, staging activation, or operational
analysis was introduced. M5 remains the future owner of approved cue/fade
application and crossfade execution.

The next permissible item is separately approved **M3.7 — provider-neutral
metadata-candidate boundary**. External tooling, worker/persistence/staging
activation, real-media detection, or operational use require separate explicit
approval and content-free evidence.
