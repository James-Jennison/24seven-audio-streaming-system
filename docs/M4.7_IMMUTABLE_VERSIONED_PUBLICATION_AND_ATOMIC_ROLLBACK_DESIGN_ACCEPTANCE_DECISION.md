# M4.7 Immutable Versioned Publication and Atomic Rollback Design Acceptance Decision

## Decision and boundary

**Status: accepted 2026-08-05 UTC; local-only and non-operational.** This
decision accepts [M4.7's immutable versioned publication and atomic rollback
design](M4.7_IMMUTABLE_VERSIONED_PUBLICATION_AND_ATOMIC_ROLLBACK_DESIGN.md)
under its separate owner approval. It accepts only deterministic, in-memory
artifact/version and active-pointer modeling; it does not expose publication to
an API/UI or execute a schedule.

It authorizes no M4.8 API/UI work, database connection, migration, media or
metadata access, runtime consumption, queue control, encoder, Icecast,
deployment, or production activity.

## Accepted evidence

| Required criterion        | Accepted evidence                                                                                                                      |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Immutable versions        | Compatible approved proposals create frozen, monotonically numbered opaque artifacts; historical versions remain retrievable.          |
| Atomic publish failure    | Incompatible candidates fail before a version/pointer change, preserving the last active version.                                      |
| Non-destructive rollback  | Rollback changes only the active pointer and appends a record; both historical versions remain unchanged.                              |
| Idempotency and authority | Publication/rollback IDs are idempotent and require a trusted prevalidated CSRF assertion plus station-scoped publisher authorization. |
| Station isolation         | Public out-of-scope versions return `not_found`; trusted candidate mismatch returns `station_reference_forbidden`.                     |
| Content-free evidence     | Records contain only opaque IDs, safe version/category fields, and UTC time; tests reject content, credential, token, CSRF, and SQL.   |
| Non-dispatch              | Static coverage proves no filesystem, network, persistence, worker, runtime, encoder, relay, or Icecast adapter import or invocation.  |

The focused compiled test and full repository quality suite pass. M4.7 did not
access media or metadata, connect to PostgreSQL, execute a migration, start a
process or service, expose a publication route, send a runtime signal, or
contact encoder, relay, Icecast, listener, DNS, deployment, or production
systems.

## Next gate

**M4.8 — API/UI authorization and safe operator visibility** is the next
sequential milestone. It requires a new explicit owner approval before work
begins. This decision neither grants nor implies that approval.
