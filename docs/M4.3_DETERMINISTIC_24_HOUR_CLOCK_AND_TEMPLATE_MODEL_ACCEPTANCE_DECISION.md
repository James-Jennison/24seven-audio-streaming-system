# M4.3 Deterministic 24-Hour Clock and Template Model Acceptance Decision

## Decision and boundary

**Status: accepted 2026-08-05 UTC; local-only and non-operational.** This
decision accepts [M4.3's deterministic 24-hour clock and template
model](M4.3_DETERMINISTIC_24_HOUR_CLOCK_AND_TEMPLATE_MODEL.md) under its
separate owner approval. It accepts only a deterministic, in-memory civil-day
planning input; it does not create a schedule or control time.

It authorizes no M4.4 policy work, live wall-clock, instant conversion, asset
or media query, database connection, migration, schedule generation, approval,
publication, runtime timing, encoder, Icecast, deployment, or production
activity.

## Accepted evidence

| Required criterion     | Accepted evidence                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Deterministic ordering | Repeated template/date fixtures produce identical, ascending local-minute slot order.                                                 |
| 24-hour input          | Contiguous opaque slots must cover exactly 1,440 local civil minutes.                                                                 |
| Timezone and DST       | IANA zones are validated; short and long DST dates retain a safe unresolved 1,440-minute civil template.                              |
| Station isolation      | Public out-of-scope lookup returns `not_found`; trusted ownership mismatch returns `station_reference_forbidden`.                     |
| Content-free output    | Inputs and summaries contain opaque IDs, safe counts, civil date/timezone, ordering, and unavailable state only.                      |
| Non-dispatch           | Static coverage proves no filesystem, network, persistence, worker, runtime, encoder, relay, or Icecast adapter import or invocation. |

The focused compiled test and full repository quality suite pass. M4.3 did not
read the wall clock, access a filesystem or media, connect to PostgreSQL,
execute a migration, call a provider, start a process or service, generate a
schedule, publish, or contact runtime, encoder, relay, Icecast, listener, DNS,
deployment, or production systems.

## Next gate

**M4.4 — Separation-policy model and evaluation engine** is the next
sequential milestone. It requires a new explicit owner approval before work
begins. This decision neither grants nor implies that approval.
