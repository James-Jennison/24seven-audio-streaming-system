# M3.9 Isolation, Idempotency, Failure, and Recovery Validation

## Status and purpose

**Status: completed 2026-08-04 UTC; local-only validation; non-operational.** M3.9
consolidates focused validation of the completed M3.1–M3.8 Programming Control
Plane contracts and the disabled M3.4 future-worker boundary. It adds no
runtime capability, persistence activation, media handling, or dashboard
command.

This is the completion and acceptance record for [M3.9 in the authoritative
roadmap](ROADMAP.md#m39--isolation-idempotency-failure-and-recovery-validation).
It depends on M3.1–M3.8 only. Completing it does not authorize M3.10, M4, or
any operational action.

## Validated local contract

The focused `m3.9-validation` test verifies all of the following with
deterministic opaque fixtures only:

- station-scoped public reads return `not_found`, while explicit internal
  cross-station relationships return `station_reference_forbidden`;
- station-local duplicate validation and disabled-worker previews return their
  original immutable record, not a second attempt;
- illegal lifecycle transitions fail as `invalid_lifecycle_transition`;
- source outcomes, recovery authorization, disabled dispatch previews, and
  retry-eligibility records are immutable append-only values;
- quarantine/failure recovery requires an explicit retained authorization and
  remains `disabled` and non-dispatching; and
- evidence contains only opaque IDs, station IDs, safe categories, counts, and
  UTC timing. The focused assertions reject content-bearing fields.

The suite also statically verifies that the M3 route module has no command
route for processing, dispatch, execution, runtime, encoder, relay, or
Icecast work and imports no filesystem, network, or child-process adapter.
The dashboard assertions preserve accessible `aria-disabled` unavailable
affordances, explicit fixture/example labeling, and no operational control or
station-data endpoint.

## Acceptance criteria and evidence

| Station isolation                 | Focused fixture tests distinguish `not_found` from `station_reference_forbidden` across source and disabled-worker references.   |
| Idempotency                       | Repeated station-local source validation and preview requests return the original frozen result.                                 |

The existing focused M3 domain, repository, route, source-reference,

## Explicit exclusions and operational proof

M3.9 does not read or accept real media, access a source reference, create or
execute a migration, activate persistence, start a container, worker,
subprocess, parser, FFmpeg, or other media tool, call a provider, contact
playout/runtime, encoder, relay, or Icecast systems, deploy, or change
infrastructure. It does not introduce SQLite.

The Programming Control Plane, Playout & Automation Runtime, Source Encoder
Layer, and Listener-Facing Icecast Layer remain independently deployable and
strictly decoupled. No UI or API action can implicitly initiate another plane.
All M3.9 evidence is content-free and contains no programming payload, media
content, title, filename, path, URL, metadata, credential, token, CSRF value,
or raw SQL.
