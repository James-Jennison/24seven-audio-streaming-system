# M4.9 Local Validation and Controlled Staging Rehearsal Proposal

**Status: accepted local validation and proposal only; non-operational.** M4.9
records the deterministic local evidence for M4.1–M4.8 and defines the exact
future approval boundary for a staging-only publication rehearsal. It performs
no staging action.

## Local evidence

The repository quality gate validates deterministic catalog eligibility,
civil-day templates, separation, dry-run previews, approval/rejection,
immutable publication modeling, rollback, API/UI isolation, content-free
output, and unavailable downstream planes. M4 inputs are opaque and scoped by
`id + station_id`; public out-of-scope lookup is `not_found` and trusted
cross-station references are `station_reference_forbidden`. Publication is
always distinct from M5 `Executed`.

## Future staging rehearsal proposal

Any rehearsal requires a new one-action owner authorization that names a
reviewed commit, opaque isolated non-production target, limited publisher and
evidence authorities, bounded input artifacts, UTC window, stop conditions,
cleanup owner, and rollback-versus-forward-fix owner. Before an action it must
prove the target is isolated/non-production, the M5/M7 planes are inactive,
and the reviewed artifact is compatible. It may validate only a bounded
station-scoped proposed-to-published and rollback pointer lifecycle with
content-free evidence. It must stop and clean up on target ambiguity,
compatibility failure, unexpected runtime path, cross-station relationship, or
any listener-facing dependency.

This proposal authorizes no migration, PostgreSQL connection, media access,
filesystem action, service/container/worker start, runtime consumption, audio
output, encoder, relay, Icecast, DNS, deployment, public listener, or
production action. It creates no standing authorization.
