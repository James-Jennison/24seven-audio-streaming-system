# M4.6 Proposed-Schedule Approval Workflow Acceptance Decision

## Decision and boundary

**Status: accepted 2026-08-05 UTC; local-only and non-operational.** This
decision accepts [M4.6's proposed-schedule approval
workflow](M4.6_PROPOSED_SCHEDULE_APPROVAL_WORKFLOW.md) under its separate owner
approval. It accepts only deterministic, in-memory approval or rejection of a
complete opaque proposal; it does not publish or execute a schedule.

It authorizes no M4.7 publication work, API/UI action, database connection,
migration, catalog/asset mutation, media or metadata access, runtime signaling,
encoder, Icecast, deployment, or production activity.

## Accepted evidence

| Required criterion       | Accepted evidence                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Complete immutable input | Only complete M4.5 previews are accepted; frozen snapshots prevent later input change, requiring a new proposal for rework.           |
| Explicit authorized flow | Review requires a trusted prevalidated CSRF assertion, allowed programming role, and station-scoped reviewer assignment.              |
| Append-only decision     | Same review ID is idempotent; another review cannot overwrite an approval or rejection for the named proposal.                        |
| Rejection and rework     | Rejection records only `new_proposal_required`; no automatic replacement, approval, or publication occurs.                            |
| Station isolation        | Public other-station records return `not_found`; trusted proposal/authorization mismatches return `station_reference_forbidden`.      |
| Content-free evidence    | Records expose only opaque IDs, safe decision/category, and UTC time; tests reject content, credential, token, CSRF, and SQL output.  |
| Non-dispatch             | Static coverage proves no filesystem, network, persistence, worker, runtime, encoder, relay, or Icecast adapter import or invocation. |

The focused compiled test and full repository quality suite pass. M4.6 did not
access media or metadata, connect to PostgreSQL, execute a migration, start a
process or service, expose an API/UI approval route, publish or execute a
schedule, or contact runtime, encoder, relay, Icecast, listener, DNS,
deployment, or production systems.

## Next gate

At the time of this decision, **M4.7 — Immutable versioned publication and
atomic rollback design** was the next sequential milestone and required a new
explicit owner approval before work began. This decision neither granted nor
implied that approval.
