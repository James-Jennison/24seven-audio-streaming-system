# M4.5 Dry-Run Generation, Conflict Reporting, and Preview Acceptance Decision

## Decision and boundary

**Status: accepted 2026-08-05 UTC; local-only and non-operational.** This
decision accepts [M4.5's dry-run generation, conflict reporting, and
preview](M4.5_DRY_RUN_GENERATION_CONFLICT_REPORTING_AND_PREVIEW.md) under its
separate owner approval. It accepts only deterministic, in-memory proposal
preview evaluation; it does not create a persisted schedule proposal.

It authorizes no M4.6 approval work, catalog/asset mutation, media or metadata
access, database connection, migration, publication, execution, runtime,
encoder, Icecast, deployment, or production activity.

## Accepted evidence

| Required criterion    | Accepted evidence                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Deterministic preview | Repeated same-station/day/request fixtures produce the same frozen opaque preview and deterministic candidate order.                  |
| Conflict reporting    | Separation conflicts are reported with safe categories and opaque references; another valid opaque candidate may fill a slot.         |
| Incomplete safe stop  | Empty, conflicted, or indeterminate plans return `incomplete` with no retained partial assignments or inferred replacement content.   |
| Station isolation     | Public other-station day reads return `not_found`; trusted day/candidate mismatches return `station_reference_forbidden`.             |
| Content-free evidence | Preview evidence exposes only opaque IDs, safe state/category fields, and counts; tests reject content-bearing output.                |
| Non-dispatch          | Static coverage proves no filesystem, network, persistence, worker, runtime, encoder, relay, or Icecast adapter import or invocation. |

The focused compiled test and full repository quality suite pass. M4.5 did not
access media or metadata, connect to PostgreSQL, execute a migration, start a
process or service, persist, approve, or publish a schedule, or contact
runtime, encoder, relay, Icecast, listener, DNS, deployment, or production
systems.

## Next gate

At the time of this decision, **M4.6 — Proposed-schedule approval workflow**
was the next sequential milestone and required a new explicit owner approval
before work began. This decision neither granted nor implied that approval.
