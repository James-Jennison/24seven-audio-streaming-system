# M4.5 Dry-Run Generation, Conflict Reporting, and Preview

## Status, purpose, and authority

**Status: local-only Control Plane contract and deterministic fixture boundary;
non-operational.** M4.5 composes accepted M4.2 opaque catalog candidates, an
M4.3 civil-day input, and M4.4 separation evaluation into a deterministic,
read-only station schedule preview. It is the execution record for [M4.5 in
the authoritative roadmap](ROADMAP.md#m45--dry-run-generation-conflict-reporting-and-preview)
and depends on accepted M4.1–M4.4.

M4.5 authorizes no catalog/asset mutation, media or metadata access, database
connection, migration, approval, publication, execution, runtime, encoder,
relay, Icecast, deployment, or production activity.

## Dry-run proposal contract

`M4DryRunPreviewBoundary` accepts only frozen, station-scoped M4 planning
inputs and an opaque request ID. It sorts eligible opaque candidates by ID,
evaluates them against the supplied M4.4 policy boundary for each ordered M4.3
slot, and returns one of these read-only outcomes:

- `complete`: every civil-day slot has exactly one opaque candidate assignment;
- `incomplete`: the catalog is empty, a separation key is unavailable, or no
  eligible candidate can fill a required slot.

The output contains only opaque preview/day/slot/candidate/policy references,
safe state/category fields, and safe counts. Repeating the same station, day
input, and request ID returns the same frozen result. It creates neither a
stored proposal nor an approval candidate.

An incomplete preview always has an empty `assignments` collection. Its
content-free conflict report preserves only the safe category and opaque
references needed for a later correction; it retains no partial or inferred
replacement schedule content. M4.5 does not silently skip a missing
separation key or policy conflict.

## Isolation, evidence, and non-dispatch

Every public read requires `station_id + day_input_id`; an out-of-scope day
input returns `not_found`. Trusted internal day-input or candidate ownership
mismatches return `station_reference_forbidden`. Candidate and day inputs are
snapshotted and frozen; the boundary has no mutator, persistence, filesystem,
network, process, worker, runtime, encoder, relay, Icecast, listener, DNS, or
deployment adapter.

Evidence uses only `m4.dry_run_preview_generated`, opaque IDs, preview state,
safe categories, and count fields. It never contains asset/media contents,
titles, artist data, filenames, paths, URLs, metadata, credentials, tokens,
CSRF values, raw SQL, or raw error data. The result is explicitly
`execution: unavailable`: dry-run generation is not approval, publication, or
execution, and no UI/API route invokes this boundary.

## Four-plane boundary and next gate

M4.5 belongs only to the Programming Control Plane. The Playout & Automation
Runtime, Source Encoder Layer, and Listener-Facing Icecast Layer remain
separately deployable and unavailable. PostgreSQL remains the sole future live
persistence target; this in-memory planning boundary introduces no SQLite,
SAM, PAL, or SHOUTcast dependency.

**M4.6 — Proposed-schedule approval workflow** is next. It remains unstarted
and requires a new explicit owner approval before work begins.
