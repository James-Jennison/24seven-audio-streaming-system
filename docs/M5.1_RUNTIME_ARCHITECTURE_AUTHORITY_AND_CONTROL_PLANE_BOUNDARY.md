# M5.1 Runtime Architecture, Authority, and Control-Plane Boundary

## Status and scope

**Status: local-only implementation and acceptance record; non-operational.**
M5.1 defines the authority boundary between the Programming Control Plane and
the future Playout & Automation Runtime. It is the authoritative execution
record for [M5.1 in the roadmap](ROADMAP.md#m51--runtime-architecture-authority-and-control-plane-boundary).

It establishes a versioned, station-scoped, content-free unavailable-observation
contract and a fixed writer matrix. The implementation is an in-memory
validator/read-only status boundary only. It has no daemon, supervisor,
worker, process, route, persistence, filesystem, network, device, encoder,
relay, Icecast, listener, or deployment adapter.

M5.1 does not authorize M5.2 or any later work.

## One-way authority matrix

| Plane                         | Programming state | Runtime observations | Output control |
| ----------------------------- | ----------------- | -------------------- | -------------- |
| Programming Control Plane     | write             | read-only            | none           |
| Playout & Automation Runtime  | read-only         | write                | none           |
| Source Encoder Layer          | none              | read-only            | none           |
| Listener-Facing Icecast Layer | none              | read-only            | none           |

The Control Plane owns programming configuration and M4 publication state. It
may display a runtime observation but cannot write it, command a runtime, or
infer runtime state from a publication. The future Runtime alone creates its
own playback and health observations. M5.1 represents only the explicit
`unavailable` / `safe_stop` state, so it cannot claim playback, output health,
or listener availability.

The Runtime is separately deployable and supervised in later M5 work; M5.1
does not create a supervisor or worker. The Source Encoder Layer and
Listener-Facing Icecast 2.x Layer remain separately deployable future planes.
Neither receives Control Plane commands or runtime output authority here.

## Contract and isolation

Each observation contains only an opaque observation ID, `station_id`, opaque
runtime-instance ID, fixed contract version, UTC observation time, sequence,
and safe availability/status categories. Every lookup and trusted relationship
uses `id + station_id`:

- a public missing or out-of-scope observation returns `not_found`;
- a trusted internal station mismatch returns `station_reference_forbidden`;
- duplicate scoped observations fail closed; and
- any state other than `unavailable` / `safe_stop` is rejected.

The contract is content-free. It never includes programming payloads, media
content, names, titles, paths, URLs, metadata, credentials, tokens, CSRF
values, configuration, or SQL.

## Permanent exclusions

M5.1 introduces no published-schedule consumption, queue mutation, media or
asset access, DSP, cue/fade execution, automation, PostgreSQL connection,
migration, SQLite, container, worker, subprocess, hardware/device control,
direct HTTP/UI runtime control, encoder/relay/Icecast action, network output,
DNS, deployment, production access, SAM, PAL, or legacy SHOUTcast dependency.

`Published (Versioned)` remains distinct from `Executed (Runtime)`. No UI or
API action can invoke the M5.1 boundary or trigger a runtime effect.

## Acceptance evidence and next gate

Focused coverage verifies the complete writer matrix, unavailable-only
validation, station isolation, `not_found` versus
`station_reference_forbidden`, content-free status output, and static absence
of process, persistence, network, and downstream adapters. Repository quality
gates provide the local acceptance evidence.

**M5.2 — Published-schedule consumption contract** is the next sequential
milestone. It requires separate owner approval. It must consume only verified
M4 Published artifacts and remains local/static; it is not authorized by this
record.
