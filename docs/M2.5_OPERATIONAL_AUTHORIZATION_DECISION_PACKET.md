# M2.5 Operational-Authorization Decision Packet

## Status and purpose

**Status: finalized decision-only governance record; non-operational.** M2 is
formally accepted for isolated staging persistence and disaster-recovery
readiness. This packet does not reopen M2, create a standing approval, or
authorize a staging operation. It gives the designated owner one bounded way
to decide whether a future, separately scoped staging action may proceed.

The accepted M2 outcome is recorded in the
[M2 acceptance and staging-readiness decision](M2_ACCEPTANCE_AND_STAGING_READINESS_DECISION.md).
It covers only the evidence already accepted: PostgreSQL-only live persistence,
loopback-only non-public staging, migration and seed, authority separation,
topology, verified backup, isolated restore rehearsal, 24-hour RPO, four-hour
RTO, and recovery-target cleanup.

## What this packet does not authorize

This packet does not authorize or schedule Compose startup, database
connection, migration, seed, backup, restore, recovery target, topology
change, credential/reference use, application or control-plane activation,
runtime work, media ingestion, playout, encoding, relays, Icecast,
SHOUTcast, listener-facing work, deployment, production access, or M3.

PostgreSQL remains the sole live persistence store; SQLite is test-only and
forbidden from the live path. Every future scoped action must preserve
`id + station_id` isolation, `not_found` for missing or out-of-scope resources,
`station_reference_forbidden` for cross-station references, and content-free
audit/evidence records.

## Future authorization gates

An owner must issue a new, explicit approval for exactly one bounded action.
The approval must name the action class, reviewed source artifact, isolated
target classification, accountable authority class, UTC change window,
content-free evidence boundary, stop conditions, and decision owner. It must
not contain credentials, secret-reference values or paths, DSNs, private
addresses, role names, raw SQL, database content, or backup content.

| Future action class                    | Separate approval must establish                                                                                                                     | Required content-free result                                                                 |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Compose or service startup             | Exact service set, isolated target classification, loopback/non-public binding, approved operator, and shutdown boundary                             | Service-set, exposure, and final-state pass/fail only                                        |
| Migration or seed                      | Reviewed commit and manifest, distinct migrator authority, recovery-point decision, transaction/seed stop path, and verification probes              | Manifest, transaction, ledger/schema, five-station, and station-isolation pass/fail only     |
| Staging application/runtime activation | Exact plane, runtime authority boundary, approved listener binding, and explicit exclusion of all other planes                                       | Plane inventory, authority, station-isolation, and inactive-plane pass/fail only             |
| Backup or restore                      | Verified artifact/recovery method, separate backup or restore authority, isolated source/target classification, RPO/RTO target, and cleanup boundary | Integrity/attribution, recovery validation, RPO/RTO, cleanup, and final-state pass/fail only |
| Topology or configuration change       | Versioned configuration artifact, intended network/volume/service boundary, impact assessment, and rollback/forward-fix owner                        | Boundary comparison, safe outcome, and residual-risk reference only                          |
| Credential or opaque-reference use     | Purpose-bound authority class, approved local mechanism, expiry/rotation owner, and proof that no value enters project evidence                      | Reference-category presence/usable pass/fail only                                            |
| Promotion or production-related action | A distinct production plan, production authority, rollback decision, and a new explicit owner approval                                               | This packet supplies no production evidence or approval                                      |

The completion of any row does not authorize another row, retry, broader scope,
or a later milestone.

## Evidence, stop, and decision rules

Every authorized run must emit only content-free evidence: UTC time,
reviewed artifact identity, authority class, opaque evidence reference,
approved probe outcomes, service-state outcome, and residual-risk decision.
It must never emit credentials, session values, tokens, DSNs, role or grant
details, raw SQL, database rows, programming payloads, media, archive contents,
or raw command output.

Stop immediately and return to the owner if the target is ambiguous or not
isolated, a listener is public or unknown, an authority is missing/shared or
over-privileged, artifact integrity is unverified, a required evidence record
would leak protected information, scope changes, or an unexpected service or
cross-plane path appears. The owner—not an operator or automation—must decide
whether a stopped change is rolled back, forward-fixed under a new bounded
approval, or deferred. No automatic retry, rollback, recovery, credential
substitution, or privilege expansion is permitted.

## Plane separation

The Programming Control Plane, Playout & Automation Runtime, Source Encoder
Layer, and Listener-Facing Icecast Layer remain independently deployable and
decoupled. A future approval for one plane does not authorize a database,
network, service, or control path for another plane. No control-plane UI or API
action may implicitly trigger ingestion, playout, encoder, relay, or streaming
work.
