# M4.7 Immutable Versioned Publication and Atomic Rollback Design

## Status, purpose, and authority

**Status: local-only Control Plane contract and deterministic fixture boundary;
non-operational.** M4.7 turns one approved, complete M4.6 proposal into an
immutable, versioned, opaque schedule artifact and models an atomic active
pointer change. It is the execution record for [M4.7 in the authoritative
roadmap](ROADMAP.md#m47--immutable-versioned-publication-and-atomic-rollback-design)
and depends on accepted M4.1–M4.6.

M4.7 authorizes no API/UI route, database connection, migration, media or
metadata access, runtime consumption, queue control, encoder, relay, Icecast,
deployment, or production activity.

## Publication and rollback contract

`M4SchedulePublicationBoundary` accepts only a station-scoped publication
candidate containing a complete proposal, its immutable approved decision, and
an opaque compatibility check. A compatible candidate creates a permanent,
monotonically numbered version with frozen opaque slot/candidate assignments.
The version is `published_versioned` but always `execution: unavailable`.

Publication is atomic in the local model: all proposal, approval,
compatibility, authorization, and idempotency checks finish before the version
and active-pointer records are created. A failed compatibility check creates no
version and does not change an existing active pointer. Repeating the same
publication ID returns the original record; a reviewed proposal cannot receive
another published version.

Rollback accepts only an existing same-station historical version and changes
the active pointer to that target. It creates an append-only rollback record;
neither the prior active version nor the target is mutated, deleted, or
renumbered. Repeating the same rollback ID is idempotent.

Publisher authorization is a trusted, token-free prevalidated CSRF/session
assertion for a station-scoped owner or administrator. No credential, cookie,
or CSRF value is accepted, retained, or emitted. M4.8 owns any future API/UI
surface for this local model.

## Isolation, evidence, and non-dispatch

Public publication, version, active-pointer, and rollback operations require
`id + station_id`. Missing or out-of-scope resources return `not_found`.
Trusted cross-station candidate references return
`station_reference_forbidden`. Evidence contains only opaque IDs, safe version
numbers, categories, and UTC times; it never contains schedule content, media,
metadata, titles, filenames, paths, URLs, credentials, tokens, CSRF values,
raw SQL, or raw errors.

The boundary has no filesystem, network, database, process, worker, runtime,
encoder, relay, Icecast, listener, DNS, deployment, or dispatch adapter.
Publication is never execution, and no future M5 consumer is introduced here.

## Four-plane boundary and next gate

M4.7 belongs only to the Programming Control Plane. The Playout & Automation
Runtime, Source Encoder Layer, and Listener-Facing Icecast Layer remain
separately deployable and unavailable. PostgreSQL remains the sole future live
persistence target; this fixture-only in-memory boundary introduces no SQLite,
SAM, PAL, or SHOUTcast dependency.

**M4.8 — API/UI authorization and safe operator visibility** is next. It
remains unstarted and requires a new explicit owner approval before work begins.
