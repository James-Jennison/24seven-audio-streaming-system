# M4.4 Separation-Policy Model and Evaluation Engine

## Status, purpose, and authority

**Status: local-only Control Plane contract and deterministic fixture boundary;
non-operational.** M4.4 evaluates approved station-scoped separation policies
against opaque M4.2 candidate references and opaque artist, title, album, or
category keys. It is the execution record for [M4.4 in the authoritative
roadmap](ROADMAP.md#m44--separation-policy-model-and-evaluation-engine) and
depends on accepted M4.2 and M4.3.

M4.4 authorizes no schedule generation, catalog or asset mutation, metadata
enrichment, media access, persistence, migration, approval, publication,
runtime enforcement, encoder, Icecast, deployment, or production activity.

## Policy and evaluation contract

Every policy carries `id + station_id`, one scope, a positive minimum candidate
distance, a deterministic non-negative precedence, and `status: approved`.
Only approved policies are accepted. Policies are evaluated in ascending
precedence, then opaque policy ID, so the first conflict is deterministic.

Candidate separation keys are opaque references only. They are not titles,
artist names, album names, categories, metadata payloads, or lookup requests.
The evaluator examines a supplied nearest-to-farthest prior-candidate order up
to each policy's distance. It does not select a candidate, assign a slot,
generate a schedule, or infer a replacement.

The result is one of `eligible`, `conflict`, `indeterminate`, or
`catalog_empty`. Missing required keys return the fail-closed
`separation_key_unavailable` category; a policy is never silently skipped or
overridden. Evidence exposes only action, station ID, opaque candidate/policy
IDs, safe outcome, and safe category, plus `execution: unavailable`.

## Isolation and non-dispatch

Public evaluation requires `station_id` and opaque candidate IDs. Missing or
out-of-scope candidates return `not_found`; trusted internal candidate or
policy ownership mismatch returns `station_reference_forbidden`. The boundary
contains no route, metadata provider, database, filesystem, network, process,
worker, runtime, encoder, relay, Icecast, listener, DNS, or deployment adapter.

It belongs only to the Programming Control Plane. The Playout & Automation
Runtime, Source Encoder Layer, and Listener-Facing Icecast Layer remain
separately deployable and unavailable.
