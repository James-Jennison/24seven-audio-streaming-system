# M3.12 Phase 1 Readiness-Plan Acceptance Decision

## Decision and exact boundary

**Decision: accepted 2026-08-04 UTC; documentation-only and
non-operational.** This decision accepts only Phase 1 of [M3.12 — Operational
Staging Activation Authorization and Isolated Media-Lifecycle
Rehearsal](M3.12_OPERATIONAL_STAGING_ACTIVATION_READINESS_AND_AUTHORIZATION_PLAN.md):
the non-executable readiness and authorization plan.

M3.1–M3.11 remain accepted in their prior local-only, non-operational scope.
This decision creates no standing authorization and grants no access to
staging, PostgreSQL, media, filesystems, backups, credentials, networks, or
any other operational resource. It does not start, perform, or approve a Phase
2 rehearsal.

## Phase 1 acceptance assessment

The accepted plan adequately defines the following without recording protected
values, target details, or execution instructions:

| Accepted Phase 1 requirement              | Decision basis                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Isolated staging classification           | Requires `isolated_staging`, `non_production`, and `empty` or `safely_classified`; the latter is a bounded safe-input decision only.                                                                                                                                                                                                  |
| Minimal future cohort                     | Limits the future cohort to `minimal_rehearsal_cohort` and does not identify, select, access, copy, name, or import real media.                                                                                                                                                                                                       |
| Separate authority and gate model         | Defines distinct one-action gates for target validation, media access, intake, processing/analysis, review, cleanup, evidence review, recovery, and Phase 2 acceptance.                                                                                                                                                               |
| Controlled future lifecycle               | Limits future categories to intake, quarantine, processing/analysis, review, cleanup, recovery/restore validation, and evidence review.                                                                                                                                                                                               |
| Stop and recovery discipline              | Requires explicit no-go conditions, named recovery ownership, and a rollback, deferral, or separately approved forward-fix decision; automatic retry, rollback, recovery, credential substitution, and privilege expansion are prohibited.                                                                                            |
| Station isolation                         | Requires `id + station_id`, `not_found` for missing/out-of-scope resources, and `station_reference_forbidden` for internal cross-station mismatches.                                                                                                                                                                                  |
| Content-free evidence                     | Prohibits media content, titles, filenames, paths, URLs, metadata payloads, credentials, tokens, CSRF values, and raw SQL.                                                                                                                                                                                                            |
| Plane separation and permanent exclusions | Keeps the Programming Control Plane, media-processing workers, Playout & Automation Runtime, Source Encoder Layer, and Listener-Facing Icecast Layer decoupled; excludes production, listener impact, scheduling, publication, playout, DSP, runtime, encoding, relay, Icecast, deployment, DNS, legacy-system changes, and M10 work. |

## What acceptance does not authorize

This decision does not select, access, copy, import, ingest, analyze,
normalize, enrich, quarantine, clean up, or otherwise handle media. It does not
connect to PostgreSQL, execute a migration, backup, restore, start a container,
worker, subprocess, FFmpeg, parser, media tool, provider, or network action.
It does not change any dashboard/API action, schedule, publication, playout,
DSP, encoder, relay, Icecast, deployment, DNS, listener, production, Windows,
SAM, PAL, or legacy SHOUTcast behavior.

PostgreSQL remains the sole future live persistence store; SQLite remains
prohibited. Icecast 2.x remains the sole future listener-facing streaming
platform. Audit and evidence remain content-free, and no dashboard or API
action may implicitly trigger an operational action.

## Next human gate and M4 deferral

The next step is a future, separately approved **M3.12 Phase 2 authorization**
for exactly one bounded action; it is not a new M3.13 milestone. Before any
Phase 2 action, the corresponding named authority must grant the plan-required
one-action approval. Each such approval is limited to its action, reviewed
artifact identity, target classification, authority category, change window,
content-free evidence boundary, stop conditions, and decision owner; completion
of one action authorizes neither another action nor a retry or broader scope.

**M4.1 — Schedule-domain and versioning contract** remains deferred until the
separately approved M3.12 Phase 2 rehearsal is completed and separately
accepted. This acceptance decision is not Phase 2 acceptance and does not
alter the M3.1–M3.11 acceptance boundary.
