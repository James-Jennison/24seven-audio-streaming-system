# M4.6 Proposed-Schedule Approval Workflow

## Status, purpose, and authority

**Status: local-only Control Plane contract and deterministic fixture boundary;
non-operational.** M4.6 accepts or rejects one named, complete M4.5 dry-run
preview under a station-scoped reviewer authorization. It is the execution
record for [M4.6 in the authoritative roadmap](ROADMAP.md#m46--proposed-schedule-approval-workflow)
and depends on accepted M4.1–M4.5.

M4.6 authorizes no API/UI route, database connection, migration, catalog/asset
mutation, media or metadata access, publication, runtime signaling, encoder,
Icecast, deployment, or production activity.

## Review and approval contract

`M4ScheduleApprovalBoundary` accepts only a frozen `complete` M4.5 preview as
a named station-scoped proposed schedule. An `incomplete` preview is not
approvable. The boundary snapshots the preview inputs at construction, so a
later caller-side change cannot alter what a reviewer sees; a correction or
rework therefore requires a new proposal ID.

A review request contains only opaque review/reviewer IDs, a safe `approved`
or `rejected` decision, and a UTC review time. It receives a trusted,
token-free authorization assertion with `csrf: validated`, an allowed
programming role, and a station assignment. The assertion represents a future
session/CSRF boundary; no CSRF value, credential, cookie, or session token is
accepted, retained, or emitted here.

The first decision creates one frozen, append-only in-memory record. Repeating
the same review ID returns that record; a different review ID cannot alter an
already reviewed proposal. An approval means only `publication: not_published`
and `execution: unavailable`. A rejection records
`new_proposal_required`; it never modifies the rejected proposal or creates a
replacement automatically.

## Isolation, evidence, and non-dispatch

Every public decision and review requires `station_id + proposal_id` or
`station_id + review_id`. Missing or out-of-scope proposals/records return
`not_found`. Trusted internal proposal/authorization scope mismatches return
`station_reference_forbidden`. Unauthorized roles return `forbidden`; a
nonvalidated CSRF assertion returns `csrf_rejected` without disclosing or
retaining a token.

Approval/rejection evidence contains only the action, opaque proposal/preview/
review/reviewer IDs, station ID, safe decision/category, and UTC time. It never
contains schedule content, media, metadata, titles, filenames, paths, URLs,
credentials, tokens, CSRF values, raw SQL, or raw errors. The boundary has no
filesystem, network, database, process, worker, runtime, encoder, relay,
Icecast, listener, DNS, deployment, or external dispatch adapter.

## Four-plane boundary and next gate

M4.6 belongs only to the Programming Control Plane. The Playout & Automation
Runtime, Source Encoder Layer, and Listener-Facing Icecast Layer remain
separately deployable and unavailable. PostgreSQL remains the sole future live
persistence target; this fixture-only in-memory boundary introduces no SQLite,
SAM, PAL, or SHOUTcast dependency.

**M4.7 — Immutable versioned publication and atomic rollback design** is next.
It remains unstarted and requires a new explicit owner approval before work
begins.
