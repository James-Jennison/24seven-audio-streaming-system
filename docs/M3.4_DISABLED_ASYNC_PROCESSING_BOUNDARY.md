# M3.4 Disabled Async Processing Boundary and Resource-Limit Contract

## Status, purpose, and non-authority

**Status: local-only implementation; disabled and non-operational.** M3.4
implements the Programming Control Plane contract for evaluating whether an
opaque, approved, station-scoped job could be accepted by a future async
worker. It does not start, queue, dispatch, or execute a worker.

This is the authoritative completion record for [M3.4 in the
roadmap](ROADMAP.md#m34--asynchronous-processing-worker-boundary). It follows
M3.1–M3.3 and does not authorize M3.5 or any later item, a migration, a
persistence activation, a staging rehearsal, media intake, filesystem access,
a provider request, runtime control, encoding, Icecast, deployment, or
production action.

## Disabled boundary contract

`ApprovedProcessingJobReference` contains only opaque `id` values and
`station_id`, the approved intake/asset/revision/source-reference relationships,
safe lifecycle/approval flags, a declared byte count, an allowlisted format
category, and a retry count. It has no filename, path, URL, media bytes, tags,
metadata payload, credential, token, or provider data.

It may be formed only when all of the following are true:

- the job lifecycle is `approved_for_processing`;
- the selected asset revision is `approved` and belongs to the same station;
- the source-reference validation state is `valid`; and
- every opaque identifier, declared size, format category, and retry count
  satisfies the bounded contract.

The local `DisabledM3AsyncProcessingBoundary` holds deterministic test job
references only. Its `status` and `preview` methods are control-plane records:
they return `disabled`/`unavailable` execution state and `dispatched: false`.
An accepted preview means only `accepted_for_future_worker`; it never means a
worker was started. A safe validation failure returns a deterministic declined
outcome. Neither outcome calls an adapter, process, filesystem, network,
provider, schedule, runtime, encoder, relay, Icecast mount, or listener-facing
service.

The prior `DeterministicM3ProcessingBoundary` remains an injectable
fixture-only analysis contract from the earlier local M3 foundation. It is not
the M3.4 dispatcher, has no default control-plane construction path, and is
used only with deterministic test fakes. Its existing result shapes are not
acceptance of M3.5, M3.6, or M3.7.

## Limits, stages, outcomes, and recovery

The immutable M3.4 contract defines, but does not enforce against real input,
the following future worker limits:

| Limit / contract                | Local contract value                                           |
| ------------------------------- | -------------------------------------------------------------- |
| Opaque-reference aggregate size | 128 bytes                                                      |
| Declared input size             | 2,147,483,648 bytes                                            |
| Wall-clock execution            | 120,000 milliseconds                                           |
| Memory                          | 536,870,912 bytes                                              |
| Concurrent jobs                 | 1                                                              |
| Retry attempts                  | 3                                                              |
| Format allowlist                | `audio/mpeg`, `audio/flac`, `audio/wav`                        |
| Future stages                   | normalization analysis, cue/fade analysis, metadata enrichment |

Each future stage has a bounded analysis-version identifier. M3.4 does not
measure loudness, derive a gain, calculate cues/fades, resolve metadata, modify
audio, or apply DSP. Those analysis contracts remain separately gated M3.5–M3.7
work; M5 alone owns future real-time DSP and playout execution.

Future attempt states are `eligible → pending → completed | failed |
quarantined`; only `failed` or `quarantined` may return to `eligible`, and only
through a retained, explicit, bounded retry decision. Safe failure categories
cover reference/input size, format, time, memory, concurrency, retry limit,
analysis-contract validation, and internal-boundary failures. Retry eligibility
is deterministic: it is available only for bounded transient categories while
the retry count remains below the configured maximum. M3.4 produces no real
attempt outcome; outcomes and retry authorization are append-only contract
values, never revision/provenance overwrites.

## Isolation, evidence, and operator visibility

All fixture jobs, preview requests, idempotency keys, dispatch outcomes, status
records, and evidence are keyed by `id + station_id`. A public scoped lookup of
a missing or other-station job returns `not_found`. An internal cross-station
relationship returns `station_reference_forbidden`. Repeating the same
station-local idempotency key and job returns the original deterministic
outcome; a different job for that key is an `idempotency_conflict`.

Evidence is content-free and limited to action, station ID, opaque entity ID,
safe category, safe count, and UTC time. No source-reference value or other
content-bearing field is included. The local API exposes only a read-only,
station-scoped processing-boundary status for an existing intake request:
`processing: disabled` and `execution: unavailable`. The existing dry-run
remains a read-only opaque-input validation. The UI exposes accessible disabled,
pending/unavailable, failed, quarantined, retry-eligible, and terminal-rejected
states, with no **Process now** action.

M3.4 remains solely in the Programming Control Plane. It cannot mutate M4
scheduling, M5 runtime/DSP, the Source Encoder Layer, relays, or the
Listener-Facing Icecast Layer. PostgreSQL remains the sole future live store;
SQLite, SAM, PAL, SHOUTcast, and other legacy runtime dependencies are not
introduced.

## Evidence and future gates

Local tests prove station isolation, `not_found`,
`station_reference_forbidden`, approval/asset-revision/source eligibility,
legal processing-attempt transitions, bounded size/format/time/memory/
concurrency/retry configuration, accepted/declined idempotent previews,
quarantine/failure/retry contracts, content-free evidence, read-only API status,
and a disabled dispatcher that cannot invoke a worker or downstream adapter.

No migration was created or executed. No persistence was activated or connected.
No container, worker, subprocess, FFmpeg, parser, media tool, filesystem/media
read, provider call, runtime/encoder/relay/Icecast contact, deployment, or
production action occurred.

The next permissible work is separately approved **M3.5 — EBU R128 measurement
and normalization recommendation contract**. Any future external-tool adapter,
worker activation, persistence activation, or staging rehearsal requires a new
explicit owner goal naming the reviewed artifact, authority, target, input
class, resource limits, rollback/stop path, and content-free evidence. M3.4
creates no standing authority for any such action.
