# M4.2 Catalog and Asset-Eligibility Boundary

## Status, purpose, and authority

**Status: local-only Control Plane contract and deterministic fixture boundary;
non-operational.** M4.2 supplies the read-only query that may project an M3
asset revision into an opaque M4 catalog candidate. It is the execution record
for [M4.2 in the authoritative roadmap](ROADMAP.md#m42--catalog-and-asset-eligibility-boundary)
and depends on accepted M3 and M4.1 records.

M4.2 authorizes no media acquisition, source resolution, metadata read or
overwrite, asset-lifecycle transition, migration, database connection, API/UI
route, schedule generation, approval, publication, runtime consumption,
encoder, Icecast, deployment, or production action.

## Eligibility contract

`M4CatalogEligibilityBoundary` accepts an M3 asset and immutable revision only
when all of the following are established:

- the asset and revision carry the same `id + station_id` scope;
- the revision belongs to the asset and has a positive immutable revision
  number; and
- the asset lifecycle state is exactly `ready_for_schedule_use`.

`superseded` assets are rejected as `asset_superseded`; every other asset state
is rejected as `asset_not_schedule_eligible`. Both rejection categories are
content-free. The boundary returns only opaque asset/revision/candidate IDs,
station ID, revision number, eligibility category, and `execution: unavailable`.
It does not return media, source, provenance, title, artist, tag, path, URL,
metadata, credential, token, SQL, or raw error data.

## Isolation, immutability, and evidence

Public evaluation requires `station_id`, asset `id`, and revision `id`.
Missing or out-of-scope resources return `not_found`. Trusted internal
relationship or ownership mismatches return `station_reference_forbidden`.
Candidate projections and evidence are frozen values; this boundary has no
method that changes M3 assets, revisions, lifecycle state, metadata, or
persistence.

Each evaluation returns content-free evidence with only the action category,
opaque IDs, station ID, eligibility outcome, and safe rejection category. The
boundary has no filesystem, network, database, process, worker, runtime,
encoder, relay, Icecast, listener, or deployment adapter.

## Four-plane boundary and next gate

M4.2 belongs only to the Programming Control Plane. It creates no schedule and
cannot dispatch a later plane. The Playout & Automation Runtime, Source Encoder
Layer, and Listener-Facing Icecast Layer remain separately deployable and
unavailable.

The next sequential work is **M4.3 — Deterministic 24-hour clock and template
model**. It remains unstarted and requires a new explicit owner approval.
